# Delegation contract

## Brief and workspace

Give an implementer a standalone brief containing the goal, scope, absolute
checkout path, owned files or boundary, constraints, acceptance observations,
and commands or recipes that prove the result. Include resolved guidance and
Active Stack Pack proof paths; require the implementer to read the applicable
pack instructions before edits. Preserve the user's external-write authority.

Run `use-git-worktree` when its trigger matches before implementation. Enter an
existing isolated checkout rather than nesting worktrees. Native host delegates
may share that checkout with exclusive filesets. Use Orca for explicitly managed
Worker Provider worktrees and terminals; obey its capability and recovery gates.
The coordinator retains research and acceptance ownership.

## Dispatch and result

Use the host's actual delegation tool and retain its child/task reference.
Default to one implementer. Parallelize only independent filesets or separate
candidate outputs, within the available worker budget. Native delegates use the host's limits;
the managed Work Unit store does not count them or enforce a machine-wide budget. Wait for terminal results;
quiet output is not completion. A failed or unavailable launch is a blocker,
not permission for coordinator implementation.

Require the implementer to return its task reference, checkout, changed files,
commands with observed results, evidence paths, and unresolved limitations.
Corrections go back to the implementer, including fixes discovered in review.
An implementer runs appropriate tests but does not accept its own work.

## Coordinator acceptance

Read the actual diff and produced files, check scope and intent, and exercise
the changed behavior or rerun a relevant reproducible check independently.
For a bug, inspect the failing-before/passing-after observation. Include the
Active Stack Pack's proof. Accept only artifacts you observed; identify every
unrun check and its reason. Return the child/result reference and evidence so
the user can inspect the handoff. Explicitly managed Work Units retain their
existing independent captured-review requirements; native delegation does not
bypass those requirements or imply managed-runtime support.
