# Disposable Android pilot

Use `packs/mobile/tests/android-pilot/` for the Gate F implementer/reviewer run. Copy it into a disposable worktree before assigning the fix. Keep the repository fixture's planted bug so another run starts from the same baseline.

## Task and evidence

The calculator charges 500 cents below a 5000-cent subtotal and should charge zero at or above 5000. The fixture deliberately charges 500 at exactly 5000. Its two baseline unit tests cover 4999 and 5001; both pass before the fix.

Give the implementer the requirement and ask for an exact-threshold regression test. Capture that test failing before the fix, then all tests passing and a debug APK build. Pass the resulting commit or patch to an independent reviewer. The reviewer must inspect the change and rerun checks in a separate checkout before acceptance.

Install the reviewed APK on the allocated emulator. Enter each subtotal, press **Calculate**, and capture the visible result:

| Subtotal (cents) | Required result |
|---|---|
| 4999 | `Shipping: 500 cents` |
| 5000 | `Shipping: 0 cents` |
| 5001 | `Shipping: 0 cents` |

A test report or APK alone does not prove emulator behavior. Preserve the build log, unit-test XML, APK checksum, emulator identity, UI dump/screenshots, reviewer verdict, and Work Unit result records together in the run evidence directory.

## Build profile

Verified on macOS arm64 with Temurin JDK 21.0.11, Gradle 8.13, Android Gradle Plugin 8.11.0, Kotlin 2.2.10, compile/target SDK 35, and minimum SDK 30. The app uses Android widgets and JUnit 4.13.2; it has no production app dependency.

From the copied fixture root:

```sh
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew :app:testDebugUnitTest :app:assembleDebug --offline --console=plain
```

Use the installed JDK 21 and SDK location on other hosts. Omit `--offline` for the first dependency download if the cache is empty. Wrapper scripts and JAR were generated by Gradle 8.13. Its distribution checksum is pinned to the value from [Gradle's checksum endpoint](https://services.gradle.org/distributions/gradle-8.13-bin.zip.sha256).

The initial verification needed online resolution of the Kotlin Android plugin marker; the subsequent test/build command passed offline. Baseline verification proves two passing tests and APK compilation only. Record the live worker and emulator results separately.

Outputs relative to the fixture root:

- APK: `app/build/outputs/apk/debug/app-debug.apk`
- Unit-test XML: `app/build/test-results/testDebugUnitTest/`
- Test report: `app/build/reports/tests/testDebugUnitTest/index.html`

## Emulator controls

Use the coordinator's allocated emulator serial; keep that allocation through teardown. The application ID is `com.hstack.gatef.pilot`, and its launcher activity is `.MainActivity`.

```sh
adb -s "$PILOT_SERIAL" install -r app/build/outputs/apk/debug/app-debug.apk
adb -s "$PILOT_SERIAL" shell am start -n com.hstack.gatef.pilot/.MainActivity
adb -s "$PILOT_SERIAL" shell uiautomator dump /sdcard/gate-f-window.xml
adb -s "$PILOT_SERIAL" pull /sdcard/gate-f-window.xml ./gate-f-window.xml
```

Run the reusable [UI proof script](../tests/verify-android-pilot.py) from the hstack root with `adb` on `PATH` and an empty evidence directory:

```sh
python3 packs/mobile/tests/verify-android-pilot.py \
  --serial "$PILOT_SERIAL" \
  --apk "$PILOT_APK" \
  --evidence-dir "$PILOT_EVIDENCE_DIR"
```

The script installs the APK, opens the activity, clears and enters each subtotal, and checks the displayed shipping charge. It finds controls by resource ID and current bounds. Each attempted result check saves XML and a PNG; `result.json` records the APK SHA256, serial, completed cases, and any failure. Device properties and install/launch output are also retained. The baseline must exit unsuccessfully at 5000; the repaired APK must pass all three cases. Use separate evidence directories for the two runs. The script leaves emulator lifecycle control with the coordinator.

Resolve controls from the current UI dump using these stable resource IDs:

| Control | Resource ID |
|---|---|
| Subtotal field | `com.hstack.gatef.pilot:id/subtotal_input` |
| Calculate button | `com.hstack.gatef.pilot:id/calculate_button` |
| Result text | `com.hstack.gatef.pilot:id/shipping_result` |

The APK uses a debug key. Keep this pilot disposable; its acceptance evidence applies to this sample and the tested hstack workflow.
