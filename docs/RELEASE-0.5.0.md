# hStack 0.5.0

## Unreleased

- **Project skill paths and agent stores use native locations** ([#34](https://github.com/hugues-vnsgn/hstack/issues/34)). The host adapters preserve existing supported project layouts and update targets, with `.claude/skills` for new Claude Code projects and `.agents/skills` for new Codex projects. Categories and verification feature maps stay with their skills. A named or existing program store wins; otherwise the agent store is `~/hstack-evidence/<date>-<task>/`. Existing store arguments and pstack's internal layout stay unchanged. Existing worker-role and gh/Origin mappings are retained; no runtime was added.

- **Mobile proof starts with a preflight** ([#75](https://github.com/hugues-vnsgn/hstack/issues/75)). Before planning lanes, the procedure records sandbox state, host, OS and tool versions, then checks each required proof tool with a real harmless operation. A blocked tool drops or replaces its lane as a gap. Before changing agent settings, the same operation runs as a host baseline. A failing baseline is a host blocker and stops settings iteration; a passing baseline routes to build-doctor. A passing step requires evidence that it was reached. These are procedure changes; host and device behavior need separate observed evidence.

- **Payload protection is withdrawn** ([#77](https://github.com/hugues-vnsgn/hstack/issues/77)). Autopilot-full and autopilot-stack no longer require a host-enforced read-only boundary around the installed plugin before write-capable work. The `payload-policy` and `helper-ready` host-tool verbs, the `--macos-mobile` recipe and the native payload-boundary regression are gone, and `worker-run` no longer treats the installed plugin or its binding as protected paths. pstack never had this layer. In hStack it turned a broken skill into a run that waited for the owner, and every problem in the #53 mobile work came from it. A mid-run skill fix now follows pstack's autonomous-run step 4: the agent fixes the skill in its own PR against the hStack repository. The plugin binding and drift checks stay, so an edit to the installed copy still holds the run. [ADR 0001](adr/0001-follow-pstack-run-safety.md) records the decision.

If you applied a `payload-policy` fragment, either the Claude Code permissions and sandbox entries or the `hstack-program` Codex permission profile, it is no longer needed and you can remove it by hand; hStack changes nothing on your machine.

- **Approved proof, `worker-run` and program control are removed** ([#80](https://github.com/hugues-vnsgn/hstack/issues/80)). The `program-check`, `artifact-hash`, `decode-design`, `worker-run`, `run-control` and `run-wait` verbs and their guides are gone. Program control takes its fan-out limits (by default one PR owner and one arena or review group at a time), its pickup of interrupted work from saved checkpoints and its device reservations with it; pstack 0.15.25 has none of them.

- **Risk-based mobile coverage is removed** ([#81](https://github.com/hugues-vnsgn/hstack/issues/81)). Plans return to pstack 0.15.25's fixed "Ten lanes on `<model>` at the PR head" rule, and `plan-check` ignores a `verification_profile` field. A plan written with risk-based lanes fails `plan-check` until its live block has the ten-lane heading and ten lanes.

- **The verification-contract gate is removed** ([#82](https://github.com/hugues-vnsgn/hstack/issues/82)). The `plan-compare` verb, its comparison helper and contract reference are gone, and `plan-check` no longer requires a contract box under "Verdict and merge". Plans again go under the agent store's `docs/` as in pstack 0.15.25, with no Git-tracked path or fenced-code rule, and a verdict is clean when every lane passes.

- **The Claude stack-permission preflight and the Astra High PR review policy are removed** ([#83](https://github.com/hugues-vnsgn/hstack/issues/83)). Autopilot-stack no longer asks for a Claude auto-mode permission preflight, and `/setup-hstack` no longer prepares one. If you added its allow rule to your Claude settings, you can remove it by hand. The host publication adapter also drops its publication-scope rule, which kept work to local commits and a PR-ready body until someone gave explicit publication scope; pstack 0.15.25 has no such rule. The hugues-mode router and autopilot-full use pstack 0.15.25's wording again. Only names, host mechanics and the router's mobile routes differ.

- **pstack's model-selection rule is back** ([#89](https://github.com/hugues-vnsgn/hstack/issues/89)). Before each spawn, the worker reference raises a role's level one step for the hardest work, lowers it one step for judgment and two or more for routine work, and uses fast mode only when the job is urgent, as pstack 0.15.25 does. Only the model names and the native agent tool's mechanics differ. The host publication adapter no longer calls an owner's differently worded skill a style preference; the bundled pinned unslop remains the prose contract.

- **Owners read bundled user-only skills by path on Claude Code** ([#48](https://github.com/hugues-vnsgn/hstack/issues/48)). Owner agents in the lab called the Skill tool on `no-comments`, `technical-writing` and `unslop`. Claude Code refused each call, and none of those owners then read the skill's file. `hugues-agent` now finds `hugues-mode/SKILL.md` itself, as pstack's `poteto-agent` does: its parent's absolute path, else the base directory Claude Code shows for the preloaded skill, else a search of the installed plugins. `host.md` and the agent header say that a bundled user-only skill is never a Skill-tool call and that `/<name>` in a playbook means reading `../<name>/SKILL.md`. The hStack-only clause that held a plan step when invocation was unavailable or denied is gone from `autopilot-full`, `autopilot-stack` and `multi-phase-plan`. Consumer and external skills stay native-only. [ADR 0002](adr/0002-read-bundled-user-only-skills-by-path.md) records the decision. The wording is a source change. A live Claude Code run of an owner-style agent is the evidence, and the pull request records it.

- **Bundled commands use the loaded plugin copy** ([#44](https://github.com/hugues-vnsgn/hstack/issues/44)). The host adapter resolves plan checks, PR watching, orchestration bookkeeping and decision-log writing from the loaded mode. Helpers carry that mode path into their own children, so consumer directories and competing plugin copies do not select the executable. Bound plan checks report the checker path, file and payload digests, and the plugin commit when available. The [host validation](installed-helper-paths-validation.md) records parent and helper runs in Claude Code and Codex.

- **Terminal and browser control procedures are bundled** ([#34](https://github.com/hugues-vnsgn/hstack/issues/34)). `control-cli` and `control-ui` ship as user-only skills from Cursor's MIT-licensed `cursor-team-kit`, pinned like `deslop`. Existing workflow steps read the complete bundled procedures. The candidate now has 57 public skills. A [local tmux check](control-skills-validation.md) passed; browser execution remains a gap because this host exposed no browser driver.
