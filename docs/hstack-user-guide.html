hStack User Guide

How to set up hStack in Claude Code and Codex, and how to use it when you are stuck, when you debug, and when you build a new feature. Written for developers working on Swift/iOS, Kotlin/Android, Kotlin Multiplatform and Compose Multiplatform apps, and for any nontrivial engineering work.

Updated 2026-10-20. Use the switch at the top right to show commands for Claude Code, Codex or both.

1. Start here

hStack is pstack for mobile development. pstack is poteto's Cursor plugin. hStack carries the same workflow to Claude Code and Codex and adds mobile proof rules for four domains: native Swift/iOS, native Kotlin/Android, Kotlin Multiplatform (KMP) shared logic and Compose Multiplatform (CMP) shared UI.

The idea fits in one sentence. You describe what you want and how you will know it is done. hStack picks a playbook, runs the right skills as each step fires, and ends with evidence you can check.

Why use it at all?

An agent left alone tends to do three things: it fixes the first plausible spot, it takes the first design it thought of, and it reports "done" because the code compiles. hStack's playbooks block each of those habits. Bugs are reproduced before they are fixed. Designs are compared before one is chosen. Results are proven on the real app, on the real target, before anyone calls them done. You stop being the person who checks every claim by hand.

How to read this guide

  • First time? Read sections 2 to 5 in order: concepts, setup, commands, then how to talk to the router.
  • Stuck right now? Jump to When you are stuck.
  • Chasing a bug? Go to Debug a bug.
  • Building something? Go to Build a new feature.

2. How hStack thinks

Five words you will see everywhere

TermWhat it isExample
RouterThe hugues-mode skill. It reads your request, matches it to a playbook and copies that playbook's steps into the todo list./hstack:hugues-mode
PlaybookAn ordered list of steps for one kind of task. There are 23 generic playbooks and 4 mobile ones.Bug fix, Feature, Babysit, mobile-proof
SkillAn instruction file for one job. Playbooks call skills as steps fire. You can also type most of them yourself.how, architect, interrogate, tdd
PrincipleA named rule of judgment. 24 of them. Saying a principle's name redirects the agent mid-task.Laziness Protocol, Prove It Works, Fix Root Causes
EvidenceWhat a run actually produced: commands and exit codes, failing-then-passing tests, screenshots, traces. "It compiles" is never evidence of behavior.RED then GREEN test output, a simulator screenshot

Two kinds of skills

Only two skills are visible to the model by default: hugues-mode and setup-hstack. Every other bundled skill is user-only. That keeps hStack's share of the host's skill list small. It has two consequences.

  • You can type any of them by name. For example /hstack:how$how or /hstack:interrogate$interrogate.
  • The router reads the rest itself. Inside a playbook, the agent opens each skill's file when a step needs it. You never have to list skills in your prompt.

Who does what

The chat you type into is the coordinator. It plans, reviews diffs and verifies. Code is written by fresh subagents (hugues-agent), and review panels run on several models. A fresh worker for each new round is the default, because chained resumes silently drop instructions. The coordinator owns every worker's output: it reads the diff and writes its own summary instead of passing a worker's claim through.

  1. Install the plugin

    The plugin lives in the GitHub marketplace hugues-vnsgn/hstack. Add the marketplace once, then install hstack@hstack.

    # Claude Code
claude plugin marketplace add hugues-vnsgn/hstack
claude plugin install hstack@hstack
claude plugin list          # should show hstack@hstack 0.5.2# Codex
codex plugin marketplace add hugues-vnsgn/hstack
codex plugin add hstack@hstack
    Try it without installing (Claude Code only)

    Clone the repository and load it for one session from your app's directory. Nothing persists after the session ends.

    git clone https://github.com/hugues-vnsgn/hstack.git ~/Codes/hstack
cd ~/path/to/your-app
claude --plugin-dir "$HOME/Codes/hstack/plugin"
  2. Restart the host

    Quit and relaunch Claude Code, or start a new Codex session. A process that was running before the install or update can keep loading its old cached copy.

  3. Confirm discovery

    In Claude Code, type /hstack: and check that hugues-mode and setup-hstack appear. In Codex, type $ and check for hugues-mode.

    If it is missing, stop

    Do not paste the path of a SKILL.md into the chat as a workaround, copy a skill under another name, or change global settings to force it on. hStack treats those as defects, not fallbacks. Check the install with claude plugin list or your Codex plugin list, and see Troubleshooting.

  4. Pick your models with setup-hstack

    Run this once in each app repository:

    /hstack:setup-hstack $setup-hstack

    Setup reads which models your host offers, asks for a reasoning budget, shows every role and lets you change any of them. It writes .hstack/models.md at your project root. Every hStack skill reads that file before it picks a subagent's model.

    BudgetEffect
    unlimitedKeeps each role at its listed effort, up to max
    largeEvery role at xhigh
    mediumEvery role at high
    smallEvery role at medium. Fewest tokens.

    Each role lists a Claude model first and a Codex model after it, for example sonnet high or gpt-6.1-sol high. Each host runs the first model it accepts, so one file serves both hosts. Panel roles (arena runners, architect runners, interrogate reviewers) hold a list, and one subagent runs per entry. A role with no line runs on inherit-parent, which means your chat's own model.

    TierClaude CodeCodexUsed for
    Workhorsesonnetgpt-6.1-solCode delegates, explorers, swarm workers
    Judgmentopusgpt-6-astraJudgment, prose, synthesizers, reviewers
    Frontierfablegpt-6-astra at xhighHardest tasks, one design or review seat, the cross-judge

    To restore a default, delete that role's line. Rerun setup at any time.

  5. Create a verification skill for your app

    For mobile projects this is required, not optional. The mobile-proof playbook needs a project verify-<app> recipe, even if XcodeBuildMCP or jev-ios-bridge can already drive the app. Setup offers to generate one. Accept. You can also run it yourself:

    /hstack:create-verification-skill $create-verification-skill

    The generator studies your repository, not you. It works out how the app launches, what can drive it, and what evidence proves each feature. It writes verify-<app>/ under your .claude/skills/ or .agents/skills/ folder, with Launch, Doctor, Drive, Evidence and Cleanup sections and a feature map. It proves one feature end to end before handing it over. Commit it so every person and agent drives the app the same way.

    Why this pays off the most

    An agent that can check its own work keeps going until the check passes. An agent that cannot hands every result back to you. Keep it honest by running /hstack:maintain-verification-skill$maintain-verification-skill regularly. It drives every mapped feature and opens at most one PR of proven corrections.

  6. Prepare the Bun helpers (only if you will babysit PRs or orchestrate)

    Run once per installed copy. Replace <plugin> with the absolute root of the copy you loaded.

    # Claude Code default root
cd ~/.claude/plugins/cache/hstack/hstack/0.5.2/skills/hugues-mode/scripts
bun install --frozen-lockfile
bun ./watch-pr/watch-pr --help# Codex default root
cd ~/.codex/plugins/cache/hstack/hstack/0.5.2/skills/hugues-mode/scripts
bun install --frozen-lockfile
bun ./watch-pr/watch-pr --help

    The --help call must exit 0. It also writes the install key the helpers check before running.

  7. Run a first small task

    Start read-only, so you can see the routing before anything changes:

    /hstack:hugues-mode preview only. explain how search submission works in this app. name the relevant files, the playbook you would pick and any open questions. do not edit or run the app.$hugues-mode preview only. explain how search submission works in this app. name the relevant files, the playbook you would pick and any open questions. do not edit or run the app.

    Then authorize a scoped change:

    /hstack:hugues-mode fix the search field clearing before submission succeeds. use a fresh worktree. you may edit the relevant source and run the existing local tests. report the reproduction, the changed behavior, the checks you ran and any proof you could not run. do not push.$hugues-mode fix the search field clearing before submission succeeds. use a fresh worktree. you may edit the relevant source and run the existing local tests. report the reproduction, the changed behavior, the checks you ran and any proof you could not run. do not push.

    Watch the todo list. Its first items are the playbook's steps, copied in. A step the agent chose to skip stays visible as skip: <reason>. The mode is sticky: it stays on for the rest of the conversation.

Update or remove

# Claude Code: update, then restart the process
claude plugin marketplace update hstack
claude plugin update hstack@hstack# Codex: update, then start a new session
codex plugin marketplace upgrade hstack
codex plugin add hstack@hstack

Keep a task that is in flight on the copy it started with until it finishes. To remove hStack, use the same host mechanism that installed it. A session-only --plugin-dir load ends with the session.

5. Talk to hugues-mode

You do not write a spec. You say what is wrong or what you want, plus anything that saves the agent time.

The five things a good prompt carries

PartWhy it mattersExample
The goalWhat is wrong, or what you want"the csv export drops its last row"
The done checkIt must be able to pass or fail. "Make it better" is not a check."done means the 60k-row fixture exports every row"
The proof you wantAsk for an artifact you can inspect"show me the row counts before and after"
What you already knowA log line or repro step saves a search"failing job id is 4812"
Constraints and authorityThese change what the agent does. A plain mode request does not let it edit, build or run your app."repro first", "don't change code yet", "you may run the simulator"
/hstack:hugues-mode the csv export drops its last row since yesterday's deploy. failing job id is 4812. repro first, then fix. done means the 60k-row fixture exports every row. show me the row counts before and after.$hugues-mode the csv export drops its last row since yesterday's deploy. failing job id is 4812. repro first, then fix. done means the 60k-row fixture exports every row. show me the row counts before and after.
Leave two things out
  • The how. Leave room for a better path than the one you would pick.
  • A list of skills. "Use /how, then /architect, then /arena" usually reorders or drops steps the playbook would have kept. Name a skill only to override a choice.

Hold back your theory of the cause at first, too. A stated guess narrows the search to wherever you pointed.

6. When you are stuck

"Stuck" means different things, and each kind has its own tool. Find your symptom below, then read the matching section.

I don't know which skill to usehugues-help

Answers, gives you a prompt and links its source. Starts nothing.

I don't understand this codehowwhyteach

Mechanics, history, or a full explanation you can argue with.

The agent misread what I wantin-your-own-wordssharpen

Surface the misreading before any code exists.

The report is noisy or vaguehugues-mode: restate it

Restate the problem first, change no code.

Every design fights backarchitectarenaPrototype

Compare real candidates instead of polishing the first idea.

Fix after fix keeps failingAttack the PremiseFix Root Causes

Question the shared premise instead of writing fix number three.

I can't tell if the result is rightinterrogateblast-radius

Other models try to break it. One safety fact gets proven by running code.

The build or toolchain is brokenbuild-doctor

Diagnose first, split host faults from agent faults.

I lost the threadrecallketchupSession pickup

Rebuild context from history, this chat, or a prior agent's branch.

Too much jargonbro

The last message again, in plain language.

The agent repeats the same mistakecorrectreflect

Turn the lesson into a check that makes the mistake impossible.

The task is too big to startfigure-it-outMulti-phase plan

A bespoke run design, or small verifiable PRs.

Ask which tool fits

/hstack:hugues-help which skill should i use to review this branch?$hugues-help which skill should i use to review this branch?

Why: a full hStack run spends real tokens. hugues-help answers from the guide and skill files and hands you a prompt to send when you are ready. It runs only when you type it.

Understand before you change anything

Agents usually fail because they misread you or because they lack context. These skills fix the second problem, and they make the agent explain itself in words you can check.

/hstack:hugues-mode investigate why background sync times out every few hours. give me what we know, what data you used, and your best hypotheses. don't change any code yet.$hugues-mode investigate why background sync times out every few hours. give me what we know, what data you used, and your best hypotheses. don't change any code yet.
/hstack:how how do we dedupe push notifications? is there an n+1 when we look up subscribers?$how how do we dedupe push notifications? is there an n+1 when we look up subscribers?
/hstack:why why was the retry limit set to five? does the reason still hold?$why why was the retry limit set to five? does the reason still hold?
/hstack:teach me how this PR changes retries. convince me it fixes the cause and not the symptom.$teach me how this PR changes retries. convince me it fixes the cause and not the symptom.

Why: how traces the runtime flow and key types. why digs through git history and whatever your MCPs expose (issues, docs, chat) and separates direct evidence from inference. "Nobody wrote down why" is a valid answer. teach builds the explanation diagram by diagram, and "convince me" turns it into an argument you can poke at.

Make sure the agent understood you

/hstack:in-your-own-words $in-your-own-words 
/hstack:hugues-mode read this thread. restate the underlying issue in your own words, in plain english. don't change any code yet.$hugues-mode read this thread. restate the underlying issue in your own words, in plain english. don't change any code yet.

Why: a misreading that shows up in a restatement costs you one message. The same misreading found after implementation costs a wrong fix. sharpen goes further: it asks how a top expert would approach the task and whether your prompt says too much or too little, then does the work.

When the design keeps fighting back

/hstack:hugues-mode prototype a few options for the onboarding screen. put them behind a switcher and send me screenshots of each on the simulator.$hugues-mode prototype a few options for the onboarding screen. put them behind a switcher and send me screenshots of each on the simulator.
/hstack:arena this, 5 candidates. the cache key format is expensive to change later.$arena this, 5 candidates. the cache key format is expensive to change later.

Why: one attempt at a hard design locks in the first shape the model thought of. A prototype answers questions by running something, not by asking you. Arena has several subagents attempt the same brief, a judge on a different model scores them, and the coordinator picks a base and grafts in the best parts of the others.

When fixes keep failing

Two failed fixes that share one premise have failed the same gate. Say the principle's name to redirect the agent:

stop. apply attack the premise. which actors hold the imbalance? question the premise before writing another fix.

For a stubborn hang, crash or leak, switch from fixing to diagnosing:

/hstack:hugues-mode new task. runtime forensics: the app's memory grows 40 MB per minute on the feed screen. find the cause with instrumentation. no fix yet.$hugues-mode new task. runtime forensics: the app's memory grows 40 MB per minute on the feed screen. find the cause with instrumentation. no fix yet.

When you lost the thread

/hstack:recall my work on the offline cache from last week, then read this bug report.$recall my work on the offline cache from last week, then read this bug report.
/hstack:hugues-mode take over this branch. read the decision log, figure out what's done, and continue from there. don't redo finished work.$hugues-mode take over this branch. read the decision log, figure out what's done, and continue from there. don't redo finished work.

ketchup summarizes what changed in this chat since your last message. bro restates the last reply without jargon.

When the agent keeps making the same mistake

/hstack:correct $correct

Why: writing the same instruction twice means the lesson belongs in structure, not text. correct tries architecture first, then types, then a lint whose error names the fix, then a test, and writes docs last. It proves each check fails on a real past mistake.

7. Debug a bug

Say what you observed and ask for a reproduction. The Bug fix playbook supplies the rest: reproduce, root-cause, fix, prove.

Step by step

  1. Describe the symptom and the authority

    State what happens, where, and what the agent may touch.

    /hstack:hugues-mode users get two notifications after a retry. repro first, then fix and verify. you may edit the notification module and run its tests.$hugues-mode users get two notifications after a retry. repro first, then fix and verify. you may edit the notification module and run its tests.
  2. Let it reproduce on the same surface

    The agent drives the app itself: verify-<app> for your app, control-ui for web and Electron, control-cli for CLIs and TUIs. It asks you to reproduce only when it can name a specific reason the surface cannot reach the bug. If the bug will not fire, it synthesizes the trigger or adds instrumentation until it does.

  3. Watch the hypotheses get eliminated

    It lists candidate causes, seeded by how over the subsystem and why for regression history, then takes the split that rules out the most each pass. When state is unclear, it adds logging and reads it as the code runs. It does not guess.

  4. Review the plan for the fix

    If the fix crosses a function boundary, architect runs first. A subagent then implements it with a specific scope.

  5. Check RED then GREEN

    The failing repro lands in git history before the fix. For mobile bugs, a fresh regression worker writes the test and it must fail on the unfixed code. A separate fresh worker then fixes production code, and the same test must pass. When an automated test is impractical, the agent records the concrete reason and an executable runtime reproduction instead.

  6. Read the reply

    It names what was broken, the root cause, the fix and how it was verified, with failing-then-passing output pasted verbatim. "Inconclusive" or a wrong target is flagged, never counted as a pass.

Why this order

Every shipped line traces to runtime evidence. A change that "might help" is a hypothesis, and hypotheses do not ship. When evidence refutes one, the agent reverts what it motivated. The result is the smallest change the evidence justifies, with a regression test that proves the bug existed.

8. Build a new feature

State the behavior you want and what must not change. The Feature playbook makes the agent learn the code, design before writing, and prove the result on the matching surface.

Step by step

  1. Say the behavior and the invariants 
    /hstack:hugues-mode add a "save for later" action to cart items. existing checkout behavior stays identical. verify on ios and android with screenshots.$hugues-mode add a "save for later" action to cart items. existing checkout behavior stays identical. verify on ios and android with screenshots.
  2. Prototype open questions first (optional)

    If you do not know what it should look like, settle it by running something:

    /hstack:hugues-mode prototype three layouts for the save-for-later list. screenshots of each on the simulator. no production code.$hugues-mode prototype three layouts for the save-for-later list. screenshots of each on the simulator. no production code.
  3. Review the design if the stakes are high 
    /hstack:architect with checkpoint. design the saved-items store before writing any code. i care most about how the cart screen uses it.$architect with checkpoint. design the saved-items store before writing any code. i care most about how the cart screen uses it.

    architect grounds itself with how, then runs an arena of competing sketches. Each sketch starts with how callers use it, then types, signatures and a module map. "with checkpoint" makes it stop and show you before implementing.

  4. Let it plan the throughput

    The agent writes four todo items: blocking first steps, independent workstreams, shared mutable state and the smallest safe decomposition. This is where it decides what can run in parallel.

  5. Implementation runs in subagents

    The delegate gets file paths, a named data shape (a state machine over scattered booleans, a typed model over repeated shape assumptions) and success criteria. When several valid shapes exist, it runs an arena so the alternatives surface and a cross-judge guards the pick. That arena is mandatory.

  6. Proof on every affected target

    A build is not behavior proof, and one target never proves the other. KMP and CMP changes need evidence from both Android and iOS. See Prove it on device.

  7. Review and PR

    Contested designs get interrogate. Then Opening a PR rebases into small ordered commits, runs deslop and no-comments, and writes the description with unslop.

Why design comes first

The two most common design mistakes are taking the agent's first design and polishing a plan that no code has tested. The Feature playbook fixes both: prototypes answer open questions, arena compares real candidates, and adversarial review goes on a diff instead of an abstract plan.

How much design does a task deserve?

9. Prove it on device

"It compiles" is not evidence. Mobile proof binds a target, a command and the artifacts it produced.

What the proof lane checks

  • Preflight. One real, harmless operation per required tool, under the agent's current settings: the Gradle wrapper's help task, adb devices, xcrun simctl list devices available. A version listing alone does not count.
  • Host baseline. When a tool is blocked, the agent runs the same command outside the agent before touching any settings. If the baseline fails, it reports a host blocker and stops. With the sandbox on, it prints the command for you to run in a plain terminal.
  • Native helpers. Xcode, SwiftPM and Gradle commands run through hStack's native execution helpers. They keep every attempt's full logs and native reports and return a bounded summary. Zero selected tests, stale artifacts or the wrong target never pass.
  • Screen proof. jev-ios-bridge when it is available and permitted. Otherwise a labelled UI-test or device-tooling fallback.
  • Evidence folder. Outside both the plugin and your app repository, so it survives cleanup. It records revision, command, exit code, target identity and artifact paths.
/hstack:hugues-mode prove the save-for-later change with /verify-shop. ios and android. show me screenshots and the test counts per target.$hugues-mode prove the save-for-later change with /verify-shop. ios and android. show me screenshots and the test counts per target.
Results are never rounded up

A flaky result is reported as flaky. A skipped test is skipped. A result from a different simulator or variant is invalid for the requested target. A missing device, tool or permission is a named blocker. None of these become a pass.

Codex sandbox note

Codex can start with --add-dir <evidence folder> --add-dir <worktree root> so evidence lands in your chosen store. Directory access does not grant permission to run ADB, CoreSimulator, Gradle or SwiftPM. The agent requests escalation for each command that needs it.

10. Review and ship

Open the PR

/hstack:hugues-mode open the pr. small ordered commits, evidence in the description.$hugues-mode open the pr. small ordered commits, evidence in the description.

Opening a PR works from a worktree, rebases into small ordered commits, runs deslop on the diff and applies unslop to the description. Before review, no-comments hands the comments to a reviewer agent that did not write them. It keeps license headers, public API docs and links that explain what code cannot. Everything else goes, or comes back as a refactor flag.

Get it green with Babysit

/hstack:hugues-mode babysit this pr. get it green.$hugues-mode babysit this pr. get it green.
/hstack:hugues-mode check on pr 123. anything outstanding?$hugues-mode check on pr 123. anything outstanding?

Babysit takes blockers in order: conflicts, then review threads, then CI. It batches every known fix into one push so checks restart once. A flaky CI job gets one fresh build, never a second retry. Review comments are triaged skeptically: real findings get a fix with a red-first proof, noise gets dismissed with a concrete reason on the thread. The second prompt asks for status only and does not start the loop.

Turn on a review bot

pstack's triage text calls the review bot "Bugbot". On Claude Code and Codex it means whichever bot your repository has. hStack installs none.

  • Claude Code Review: an owner of your Claude organization turns it on (Team or Enterprise plan).
  • Claude GitHub Action: run /install-github-app in Claude Code and pick the review workflow.
  • Codex: turn on Automatic review for the repository in Codex settings, or comment @codex review on a PR.

With no bot installed, a plan's "Bugbot triage done." box reads "Not applicable. Reason no review bot."

Land it with Shipping

/hstack:hugues-mode land the stack.$hugues-mode land the stack.

Green is not safe. Shipping has one fresh agent per PR prove the behavior live, and the agent that judges a change is never the one that wrote it. It then lands only the contiguous verified run from the bottom and reports the first PR that breaks the chain.

Earn the trust before the loop

Pause and resume

/hstack:hugues-mode pause. i'm restarting claude code.$hugues-mode pause. i'm restarting claude code.

Pause safely finishes or backs out of the current step, commits a work-in-progress checkpoint and writes a resume note. Session pickup treats that trail as authoritative and verifies inherited claims instead of redoing them. Saying "keep going" never triggers a pause.

What always pauses for you

Reversible work proceeds without asking. hStack always pauses for irreversible writes: force-push to shared branches, deploys, data deletion and customer messages. Pushing, publishing, merging and releasing each need their own go-ahead.

13. Tune cost and models

hStack spends extra tokens on subagents and review panels. That is the price of the rigor. To spend fewer:

  • Rerun /hstack:setup-hstack$setup-hstack and pick a smaller budget or cheaper models. A strong chat model with cheaper code roles is a good split.
  • Set a role to inherit-parent so it runs on the chat's own model.
  • Shorten a panel list. Each entry runs one subagent.
  • Save hugues-mode for work that needs rigor. A small, obvious edit does not.

Every run that spawned workers ends with a Workers line: each role's requested and actual model and effort, plus any fallback and its reason.

14. Troubleshooting and pitfalls

ProblemWhat to do
hugues-mode does not appearCheck claude plugin list or your Codex plugin list. Restart the host. Do not paste a SKILL.md path or edit global settings to force it.
Update says "already at the latest version" but you expected new behaviorThe marketplace update only moves when the version number changes. Uninstall and reinstall to pick up a newer commit at the same version.
New version installed, old behavior persistsRestart the Claude Code process. An old process keeps its cached copy.
Mobile proof is "blocked"Read the named blocker. Usually a missing verify-<app>, a tool the sandbox denies, or missing authority in your prompt. Add the authority or run the printed host-baseline command yourself.
Babysit fails to start watch-prRun the one-time Bun setup in setup step 6 for the copy you actually loaded.
The agent treats a new question as the next feature stepStart with "new task".
Routing looks wrong in plan modePlan mode masks routing. Test routing in a normal session on a disposable copy of the app.
Parallel agents overwrite each otherAsk for "a fresh worktree off <base>" in each task.
Disk is full of worktrees and simulatorshugues-mode what's eating my disk? prune the worktrees and simulators that are safe to prune.

Pitfalls

  • Listing skills in the prompt. The playbook already sequences them.
  • Accepting a confident reply without evidence. A good reply carries commands and output. Without them, treat it as a red flag.
  • Taking "it builds" as "it works". Ask for the screen, the test counts, the stored value.
  • Interrogating a plan with no code. Reviewers invent theoretical risks. Prototype first, then review what got built.
  • Skipping cleanup. Narrating comments and defensive dead weight are where the next bug hides. Say "deslop it" before you commit.
  • Forgetting authority. "Fix it" alone does not grant edit, build or device permission in your app. Say what is allowed.

15. What is verified today

hStack's own docs separate what was observed from what was only built. As of 0.5.2:

  • Observed: installs and updates from 0.4.0 through 0.5.2 on both Claude Code and Codex. Router discovery and firing on Claude Code. Bounded bug-fix runs on both hosts. Native helper runs, including failed and incomplete attempts.
  • Not yet observed: a complete mobile journey on a real consumer project, on either host. Interactive Claude Code completion under normal permissions. Codex scheduling between turns. A real review bot reviewing an hStack PR.

The release notes in the repository (docs/RELEASE-0.5.2.md) carry the details. When the agent reports a gap, that is the system working as designed.
