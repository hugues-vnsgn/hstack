# Herdr

This page maps Herdr 0.9.5 from its own CLI reference at commit `ee5bfb5`, read on 2026-11-10. Unobserved: every row. hStack has no recorded worker run in a Herdr pane, so check a row on your Herdr before you rely on it. Each command prints JSON. A server error prints JSON on stderr with exit status 1, and a usage error exits with status 2.

| Row | Mechanics |
|---|---|
| Detect | `HERDR_ENV` is `1`. A Herdr pane also sets `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID` and `HERDR_PANE_ID` for every process it starts. |
| Sessions and worktrees | A session is a pane with an ID such as `w1:p1`. Read each ID from a command's JSON, because a closed ID is not reused. An agent target is the worker's unique name or the ID of the pane that hosts it. Make each worker's checkout with `git worktree add`. Give the worker a pane with `herdr pane split --current --direction right --cwd <abs> --no-focus`, or `--direction down` in a narrow pane, and read the new ID from `.result.pane.pane_id`. `herdr pane list --workspace "$HERDR_WORKSPACE_ID"` lists the panes. |
| Start | `<root>` is the directory above `skills/` in the path of the `hugues-mode/SKILL.md` you read. Run `herdr agent start <name> --kind claude --pane <pane_id> -- --plugin-dir <root> --model <id> --effort <level>`. Leave out `--plugin-dir` for the installed copy. `<name>` matches `[a-z][a-z0-9_-]{0,31}` and is unique among live agents. Add `--permission-mode bypassPermissions` only when the task or brief states that the owner approved it. Otherwise pass no permission flag, so the worker runs in the user's default mode, and say so on the Workers line. The start returns once Herdr sees the agent ready for input, within 30 seconds by default. `agent_not_ready` means the agent stopped at an approval or question screen: read the pane and report it. Start the prompt with `/hstack:hugues-mode`, or `$hugues-mode` for a `--kind codex` worker. In your store, record each worker's name, pane ID, worktree path, DONE time, verdict SHA and closure. |
| Send | `herdr agent prompt <name> <text>`. Success means the text and Enter were written, not that a turn started. `agent_blocked` means the agent is at an approval or question screen and nothing was sent. After a timeout or `agent_prompt_stalled`, read the pane before you send again, because the prompt may have arrived. |
| Read | `herdr agent read <name> --source recent-unwrapped --lines <n>`. `--source visible` reads the rendered screen. |
| Wait | Stop waiting at the first of three ends, and report which one it was: DONE in the status file the worker's brief names, `herdr agent wait <name> --timeout <ms>`, or that wait's timeout. The wait settles on `idle`, `done` or `blocked`. `blocked` is an approval or question screen, and `unknown` is not completion. An idle agent is not DONE. |
| Close | After DONE and its evidence, close only a pane this run created, with `herdr pane close <pane_id>`. Confirm the close with `herdr pane list`, then log it. Close a round's pane before the next round creates one. A worker is lost when `herdr agent get <name>` stops resolving it before DONE. Then report the worker lost and call it no further. |
| Load a PR head | Pass `--plugin-dir <root>` after the `--` of `herdr agent start`. Confirm from the transcript which `hugues-mode/SKILL.md` it read. |
| Allowed tools | Use the `herdr pane` commands `split`, `list`, `get`, `layout`, `read` and `close`, and the `herdr agent` commands `start`, `prompt`, `read`, `wait`, `get` and `list`. Send to and close only panes this run created. An observer only lists and reads. Nobody answers an approval or question screen in a pane. Decline a request for anything the Skip line names, say it is skipped by design, and do the work in a Herdr pane with the commands above. |
| Skip line | Skipped in Herdr: `herdr worktree`, workspace and tab creation, `herdr notification`, plugins, `--machine` and saved machines, `herdr session`, `herdr server` and `herdr integration`. hStack makes each checkout with `git worktree add` and dispatches, waits for and settles the work itself. |
